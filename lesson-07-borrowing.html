Lesson 07 Ownership 17 min

Borrowing instead of moving

A reference lets a function read or change a value without taking ownership of it. The rules are two lines long, and they prevent data races at compile time.

On this page

  1. A reference borrows
  2. A mutable reference can change it
  3. The two rules
  4. Why the rule is worth it
  5. Slices

01A reference borrows

&value creates a reference. The owner keeps the value, and the reference is only allowed to exist for a while.

measure takes &str, and &report is a &String. That works because &String coerces to &str, which is why library functions prefer &str: it accepts both a literal and a String.

02A mutable reference can change it

&mut gives read and write access. The caller must pass a mutable reference too, so the change is visible at the call site.

Inside the function you do not need to dereference to call a method. Rust inserts that for you.

03The two rules

At any moment, a value can have either:

  • any number of immutable references, or
  • exactly one mutable reference,

but never both at once. This is checked when you compile, and it is what makes Rust safe without a runtime check.

04Why the rule is worth it

An immutable borrow promises the value will not change while it is held. A mutable borrow promises nobody else is looking. Together they mean a reference can never be invalidated underneath you, which is the dangling pointer problem, solved before the program runs.

In practice you will hit these errors when you try to hold a reference across a loop that also mutates the collection. The fix is almost always to finish using the reference before mutating, or to collect what you need into a new variable first.

05Slices

A slice is a reference to part of a collection. &text[0..5] is the first five bytes, and &items[1..] is everything from the second element on.

Careful with text indexes

String slices are byte offsets, and a multi-byte character will panic if you cut it in half. For text you did not write yourself, use .chars() instead of slicing.

Exercise

Write fn longest(a: &str, b: &str) -> &str that returns whichever is longer. Call it with two literals and print the result.

Show a hint

Compare a.len() and b.len(). Both parameters and the return value need the same lifetime, which the compiler infers when there is a single output reference.
