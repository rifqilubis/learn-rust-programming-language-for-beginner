Lesson 11 Real programs 18 min

Recoverable errors with Result

A failure you can do something about is a value, not an exception. Result carries either the answer or the reason, and the question mark passes it along.

On this page

  1. Result is an enum
  2. Handling it with match
  3. The question mark
  4. Your own error type
  5. panic, and when not to

01Result is an enum

Result<T, E> is Ok(value) on success and Err(error) on failure. Parsing text into a number is the cleanest example, because it fails all the time and never crashes.

Nothing panicked. The failure is a value you can inspect, store, or pass upward.

02Handling it with match

The explicit version is a match on the two variants. It is verbose and completely clear.

The error type is named in the signature, so a caller knows exactly what can go wrong without reading the body.

03The question mark

? after an expression means: if this is Err, return that error from the current function now. If it is Ok, unwrap the value and carry on.

Without ? that loop needs a nested match in every iteration. The operator exists so the happy path stays flat and readable.

04Your own error type

When a function can fail for more than one reason, give it an error enum. Each variant names a real failure, and the caller can match on them.

Deriving Debug makes the failure printable. In a real project you would also implement Display so the message reads well for a user.

05panic, and when not to

A panic aborts the current thread. It is for a bug that should never happen, not for input you expect to be wrong.

.get() returns an Option and never panics, while numbers[index] panics on an out-of-range index. For anything driven by user input, choose the version that returns a value.

Rule of thumb

Use Result when the caller can recover. Use Option when the only information is presence or absence. Use panic! when continuing would leave the program in a state you cannot reason about.

Exercise

Write fn average(numbers: &[i32]) -> Result<f64, String> that returns an error when the slice is empty. Print the result of both an empty and a non-empty call.

Show a hint

Return Err(String::from("empty list")) early. Otherwise sum as f64 and divide by len().
