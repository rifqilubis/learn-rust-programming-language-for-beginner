Lesson 06 Ownership 18 min

Ownership: who holds the value

Every value has exactly one owner. When the owner goes out of scope the value is freed. This is the idea the rest of Rust is built on.

01The problem ownership solves

In a language with manual memory management you must free what you allocate, and forgetting is a leak while freeing twice is a crash. In a language with a garbage collector, something else decides for you and you pay for it at runtime.

Rust takes a third route. The compiler tracks which variable owns each value, inserts the free at the right moment, and rejects programs where two places would both think they own the same thing. There is no runtime cost and no collector.

02A move transfers ownership

Assigning a String to another binding moves it. The first binding is no longer usable, and the compiler enforces that.

Now try using greeting after the move:

Why forbid it? A String is a pointer, a length, and a capacity on the stack, pointing at bytes on the heap. Copying those three words would leave two owners of one allocation, and both would free it at the end of the function. Rust moves instead of copying, so there is exactly one owner.

03Simple values copy

Integers, floats, booleans, and chars live entirely on the stack, so copying them is cheap and safe. These types implement a trait called Copy, and assignment copies rather than moves.

The practical rule: if a type owns heap memory, it moves. If it is a fixed-size value, it copies.

04Passing to a function moves too

The same rule applies at call boundaries. Passing a String by value hands ownership to the function, and the caller cannot use it afterwards.

You have three ways to keep using the value: pass a reference instead (next lesson), return ownership back from the function, or clone it if a copy is genuinely what you want.

Returning the value back works, but you will quickly find it clumsy, which is exactly why references exist.

05clone when you mean a copy

.clone() makes a real, independent duplicate. It is not a bug to use it, but every clone is an allocation, so it should be a decision and not a reflex.

Scope ends, value drops

When a function ends, every value it owns is dropped in reverse order of declaration. That is where the free happens, and you never write it.
