Lesson 09 Data 18 min

Enums, match, and Option

An enum says a value is one of several things. match makes you handle every one of them. Together they replace null and most boolean flags.

On this page

  1. Variants can carry data
  2. match handles every variant
  3. Option replaces null
  4. The shortcuts worth knowing
  5. match on anything
  6. Exercise

01Variants can carry data

Each variant is a distinct shape, and each can hold different data. That is more than a C enum, which is just a number.

One type, three possible shapes, and the compiler knows all of them. That knowledge is what makes match powerful.

02match handles every variant

match compares a value against patterns and runs the first one that fits. It must be exhaustive, so a new variant becomes a compile error everywhere it is not handled.

Patterns bind the data out of the variant, so radius and the two fields are usable directly in the arm.

03Option replaces null

There is no null in Rust. A value that might be missing has type Option<T>, which is either Some(value) or None. The compiler will not let you use the value without handling the missing case.

Every place that can be empty is marked in the type. There is no way to forget to check, because forgetting means the code does not compile.

04The shortcuts worth knowing

Three methods cover most everyday uses of Option.

unwrap_or supplies a fallback. map transforms the value inside without leaving the Option. if let handles one variant and ignores the rest, which is shorter than a full match when only one arm matters.

About unwrap

.unwrap() panics on None. That is fine in a test or a prototype, and it is a real bug in a program people use. Prefer unwrap_or, unwrap_or_else, or a match.

05match on anything

match is not limited to enums. Ranges, literals, and guards work too, and the arms are checked for order.

06Exercise

Define enum TrafficLight with Red, Green, and Yellow, plus fn next(self) -> TrafficLight and fn name(self) -> &'static str returning red, green, or yellow. Start at Red, advance a mutable variable, and print four lines.

Work through these in order

  1. The enum, the #[derive(Copy, Clone)], and the main loop are already correct. Fill in next and name.
  2. In next, match on self and return the following variant: Red to Green, Green to Yellow, and Yellow back to Red.
  3. In name, match on self and return a plain string literal: "red", "green", or "yellow". Do not print; the caller prints.

Short version: Match on self in both methods. Derive Copy, Clone so the value can be used after a call. The checker asks for Red.next().next(), so next must return an owned light rather than a reference.

Reference solution

Reading or loading this does not unlock the lesson. The checker still has to run and pass your code, and loading it replaces what is in the editor.

#[derive(Copy, Clone)]
enum TrafficLight {
    Red,
    Green,
    Yellow,
}

impl TrafficLight {
    fn next(self) -> TrafficLight {
        match self {
            TrafficLight::Red => TrafficLight::Green,
            TrafficLight::Green => TrafficLight::Yellow,
            TrafficLight::Yellow => TrafficLight::Red,
        }
    }

    fn name(self) -> &'static str {
        match self {
            TrafficLight::Red => "red",
            TrafficLight::Green => "green",
            TrafficLight::Yellow => "yellow",
        }
    }
}

fn main() {
    let mut light = TrafficLight::Red;
    for _ in 0..4 {
        println!("{}", light.name());
        light = light.next();
    }
}
