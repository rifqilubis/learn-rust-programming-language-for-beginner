Vectors and strings

Two growable collections cover most programs: a list of values, and text you build at runtime. Both own their contents and both are used constantly.

On this page

  1. Creating a vector
  2. Looping and computing
  3. Strings are bytes with rules
  4. Building text from parts
  5. Removing and checking
  6. Exercise

01Creating a vector

Vec<T> is a growable array on the heap. The vec! macro is the shortest way to build one.

first() and last() return Option, because an empty vector has neither. Indexing with scores[0] panics on an empty vector instead, which is why the methods are usually the better choice.

02Looping and computing

Iterators turn a loop into an expression. sum, max, and filter are the ones you will reach for first.

.iter() gives references, so the filter closure receives &&i32 and needs two stars. collect() gathers the result into whatever type you annotated.

03Strings are bytes with rules

String is a Vec<u8> that is guaranteed to be valid UTF-8. That guarantee is why you cannot index a string by number: one character can be several bytes.

Both numbers agree here because the text is ASCII. Add an accented character and len() grows while chars().count() does not.

04Building text from parts

format! returns a new String instead of printing. join glues a collection together, and split takes it apart.

05Removing and checking

remove takes an index and shifts the rest, pop takes the last and returns it, and contains checks membership.

Capacity is not length

A vector tracks how many items it holds and how much room it has. push occasionally reallocates, which is why a &vec[0] held across a push will not compile. That error is the borrow checker saving you from a dangling pointer.

06Exercise

Given vec![4, 8, 15, 16, 23, 42], print [4, 8, 16, 42], then sum: 70, then the original vector. Both numbers come from fn evens(numbers: &[i32]) -> Vec<i32> and fn even_sum(numbers: &[i32]) -> i32, which the checker calls with other vectors.

The checker calls these

fn evens(numbers: &[i32]) -> Vec<i32>
fn even_sum(numbers: &[i32]) -> i32

Expected output

[4, 8, 16, 42]
sum: 70
[4, 8, 15, 16, 23, 42]
Stuck?

Work through these in order

  1. The main function already prints everything in the right order. You only need to implement evens and even_sum.
  2. Both functions receive a slice, &[i32], so iterate with numbers.iter(). Each item is &i32 inside the closure, which is why the check is **n % 2 == 0.
  3. .filter(...) keeps the numbers that pass the test, .copied() turns &i32 back into i32, and .collect() builds the Vec<i32> the return type asks for.
  4. For even_sum, reuse evens(numbers) and add up the result with .iter().sum(). Reusing the function you already wrote means one list of even numbers, not two separate rules.

Short version: Use .iter().filter(|n| **n % 2 == 0).copied().collect::<Vec<i32>>(), and sum with .iter().sum::<i32>(). Neither function takes ownership, which is why the original stays usable.

Reference solution

Reading or loading this does not unlock the lesson. The checker still has to run and pass your code, and loading it replaces what is in the editor.

fn main() {
    let numbers = vec![4, 8, 15, 16, 23, 42];

    println!("{:?}", evens(&numbers));
    println!("sum: {}", even_sum(&numbers));
    println!("{:?}", numbers);
}

fn evens(numbers: &[i32]) -> Vec<i32> {
    numbers.iter().filter(|n| **n % 2 == 0).copied().collect()
}

fn even_sum(numbers: &[i32]) -> i32 {
    evens(numbers).iter().sum()
}
